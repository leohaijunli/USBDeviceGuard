# devguard 界面与便捷性设计

用户追加要求：**界面要优化，便捷**（2026-11-06）。

## 核心任务

用户先确认服务状态，再找到设备、看当前问题、完成登记或应用配置。主屏围绕这条路径，不要求用户阅读原始 TOML 或知道内核端口编号才能开始。

## 布局

1. **顶部状态条**：服务状态始终可见；暂停显示类型、剩余时间与“立即恢复”。停止显示红色“未受保护”和“启动”。
2. **稳定导航**：设备、日志、策略与诊断三个入口。登记和编辑属于设备工作流，不再增加一级导航。
3. **设备工作区**：搜索与状态筛选 → 设备列表 → 选中项详情。宽窗口列表与详情并排，窄窗口详情切为可返回的单栏。
4. **底部反馈**：连接/数据时效、当前操作结果；失败信息靠近相关按钮，包含下一步。

## 缩短常用操作路径

- 搜索可匹配名称、描述、VID:PID、序列号、端口；Ctrl+K / Ctrl+F 聚焦搜索。
- 状态筛选“全部 / 待处理 / 已管理”一按切换，并有数量；筛选保留选中设备的身份，不因排序改绑到别的设备。
- 点选列表行立即在旁边看详情；详情突出稳定链接、实际端口、波特率、权限和身份绑定方式。
- 对未登记设备直接提供“登记…”；偏差设备直接提供“应用配置”；次要动作放入“更多”。
- 稳定设备路径支持复制；不在屏幕上堆叠未经请求的 shell 命令。
- 登记向导只要求补充必要字段；按类型填合理默认值，允许回退且保留输入。
- 编辑基本字段直接可见；多 ids、bootloader、流控等在明确分区中展开；保存前只呈现真正变更。
- 暂停时长用四个可见选项 5 / 15 / 30 / 60 分钟；“只暂停拦截”与“整个服务休眠”展示一句话差别。
- 停止默认勾选放行；二次确认只用于需求明确要求的禁用自启，不给低风险操作增加额外对话框。
- 日志可从设备详情直接带设备过滤进入；导出范围与当前过滤一致。

## 状态与反馈

### 窗口与后台生命周期（2026-11-07 修订）

- 右上角 `X` 和系统关闭窗口请求只隐藏 GUI 到后台，不结束进程、不停止设备监视、不调用 daemon shutdown。
- 系统托盘图标始终是恢复窗口的入口；左键激活或右键 `Show` 恢复同一窗口、当前选中设备、搜索与草稿。
- 正常退出只能通过托盘图标右键 `Exit`，它清理 GUI 自己的后台资源和图标，不停止 Linux daemon、不修改 USB 状态。
- 托盘必须先成功建立，才允许隐藏窗口；托盘不可用时不得把 GUI 藏到无法恢复的状态，必须显示明确错误。
- 菜单沿用操作系统原生菜单与键盘/可访问性行为，包含 `Show`、分隔线、`Exit`；界面及菜单文案保持英文。
- Explorer/托盘重建后恢复图标；窗口显示状态与进程运行状态分别表达，不能把隐藏称为退出。
- 本轮先在 Windows 原生桌面实现/验证；Linux 的托盘承载及 Wayland 行为另行验收，不把 Windows 结果冒充 Linux 通过。

- 状态标签必须有文字，不靠颜色辨认。
- `audit` 文案为“只记录”；`enforce` 为“拦截未登记设备”，同时保留技术名称供诊断。
- 执行中禁用重复提交，保留当前输入；授权取消/失败不清空表单。
- 服务停止保留最近快照并标明“数据可能过期”；服务状态未知应写“连接中断”，不伪装为已停止。
- 无设备、无搜索结果、未登记设备、连接失败分别有相应下一步。
- 阶段 0 的验证界面明确标注“NSH 组件验证”；不能把验证事件呈现为真实 USB 设备。

## 视觉与可访问性

- 沿用系统窗口和字体，浅/深色由 theme tokens 统一；主色用于选中/提交，橙色用于需要关注，红色用于错误/停止。
- 内容区用分隔线组织，避免卡片套卡片；行高和字距保证快速扫读。
- 全部交互使用 NSH 语义组件；Tab、Enter、Space、Escape 可操作，有可见焦点。
- 用户调整窗口、字体/缩放时，优先保留主操作；长 ID 可截断但详情可查看完整值。
- 关键操作始终有文字按钮，不依赖 hover、图标含义或右键菜单。
- 每个输入有独立标签和就近校验；输入法组合期间不重写文本。

### 窗口尺寸与滚动（2026-11-07 修订）

- 宿主窗口按逻辑点创建并随 DPI 缩放：默认 1120×760 逻辑点，居中并限制在显示器工作区内；150% 缩放下不再退化成 747×507 逻辑点。
- 最小窗口为 900×700 逻辑点（`WM_GETMINMAXINFO` 按当前 DPI 换算）；更小的屏幕仍以工作区为上限。
- 跨显示器拖动（`WM_DPICHANGED`）采用系统建议矩形并重新排布内嵌视图。
- 页面区整体可滚动，但只在内容确实高于可视区时出现；常显且可拖动的滚动条位于各列表/详情自己的滚动视口内。
- 滚动视图的内边距放在内容子视图上，避免内置滚动条把内边距重复计入滚动范围（否则每个尺寸都会多出几十点的假滚动）。
- 列表内容左右留出滚动条宽度，避免滑块压住行尾内容。

### 紧凑桌面密度与新设备提示（2026-11-07 修订）

- 顶部保留应用名、验证范围和主要操作，去掉重复口号；页面使用 16pt 内边距，列表行典型高度约 56pt，保留现有文字大小、焦点和可拖动滚动条。
- 详情使用统一标签—值列，不再给每个短字段单独占两行；标题与状态同组。长 ID 可以换行/选择/复制，长备注仍保留全宽段落。
- 首个设备快照静默建立基线；仅新出现的 USB 串口提示，同实例 ID（大小写不敏感）五分钟内去重。蓝牙虚拟端口、重复快照和 COM 改号不提示。
- 前台右下角显示 Toast，包含端口、名称、VID:PID、`View` 和 `Dismiss`；默认显示六秒，悬停和模态表单期间暂停计时。查看时选中对应设备并清除妨碍定位的设备搜索，不丢弃表单草稿。
- 设备已断开时禁用旧提示的 `View`。通知不包含放行、授权、改参数或固件操作。
- 隐藏/最小化时使用 Windows 原生托盘通知，不自动显示窗口、不抢焦点；点击通知恢复现有窗口并定位设备。窗口内提示在隐藏时保留、恢复后继续计时，隐藏时不运行 Toast 定时器。
- 系统通知是否显示受 Windows 通知设置/勿扰模式控制。Linux 桌面通知仍待单独接入，不能以 Windows 结果计为 Linux 验收通过。

## 可操作的验证标准

2026-11-08：Linux 的第一批 Devices / Logs / Policy and diagnostics 已用真实 daemon 协议接通；选择/过滤/过期回复、断开重连和停止状态经过 headless/隔离 socket 测试。编辑/应用和服务控制尚未开放，GTK/Wayland 原生外观、输入与托盘未验收；以下总验收项不因此整体勾选。详见 [`gui-daemon.md`](gui-daemon.md)。

- [ ] 搜索 → 选中 → 详情：无需离开设备页。
- [ ] 暂停入口 → 选类型/时长 → 确认；取消不改变状态。
- [ ] 表单有错误时，用户能直接找到出错字段；关闭/重开行为明确。
- [ ] 事件到达更新列表与状态，保留正在编辑的草稿。
- [ ] 长列表回收和过滤后，行内容、选中项和详情保持一致。
- [x] 浅/深色、窄/宽窗口、较大字体下内容不重叠，焦点与主要操作可见；本轮另实测非全屏默认/最小/普通三种窗口（含 150% DPI），页面内容完整、设备/记录/指南各自的滚动条常显且可拖动（2026-11-07）。
- [ ] 正式 GUI 在停止/意外断开/授权失败三种情况下行为符合需求；须阶段 6 对真实 daemon 验收。
- [x] Windows 原生回归验证 `X` 隐藏、窗口和进程保留；工程师确认 COM4 可见、托盘入口可用、`Show` 可恢复（2026-11-07）。
- [x] 工程师确认 Windows 托盘右键 `Exit` 正常退出；GUI 不发送 daemon shutdown（2026-11-07）。Linux 托盘仍待验收。
- [ ] 托盘失败不产生不可见、无法退出的孤立进程；托盘重建恢复可操作图标。
- [x] 隔离快照与真实 NSH 引擎回归覆盖新增、去重、自动关闭、断开后禁用查看、详情跳转和模态草稿保留。
- [ ] 真实插入 USB 串口时，前台 Toast、后台 Windows 通知及点击恢复完整验收；不得用隔离快照冒充物理插拔。
