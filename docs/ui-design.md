# devguard 界面与便捷性设计

用户追加要求：**界面要优化，便捷**（2026-11-06）。

## 核心任务

用户先确认服务状态，再找到设备、看当前问题、完成登记或应用配置。主屏围绕这条路径，不要求用户阅读原始 TOML 或知道内核端口编号才能开始。

## 布局

1. **顶部状态条**：服务状态始终可见；暂停显示类型、剩余时间与“立即恢复”。停止显示红色“未受保护”和“启动”。
2. **稳定导航**：设备、日志、策略与诊断三个入口。登记和编辑属于设备工作流，不再增加一级导航。
3. **设备工作区**：搜索与状态筛选 → 设备列表 → 选中项详情。宽窗口列表与详情并排，窄窗口详情切为可返回的单栏。
4. **底部反馈**：连接/数据时效、当前操作结果；失败信息靠近相关按钮，包含下一步。

## 缩短常用操作路径

- 搜索可匹配名称、描述、VID:PID、序列号、端口；Ctrl+K / Ctrl+F 聚焦搜索。
- 状态筛选“全部 / 待处理 / 已管理”一按切换，并有数量；筛选保留选中设备的身份，不因排序改绑到别的设备。
- 点选列表行立即在旁边看详情；详情突出稳定链接、实际端口、波特率、权限和身份绑定方式。
- 对未登记设备直接提供“登记…”；偏差设备直接提供“应用配置”；次要动作放入“更多”。
- 稳定设备路径支持复制；不在屏幕上堆叠未经请求的 shell 命令。
- 登记向导只要求补充必要字段；按类型填合理默认值，允许回退且保留输入。
- 编辑基本字段直接可见；多 ids、bootloader、流控等在明确分区中展开；保存前只呈现真正变更。
- 暂停时长用四个可见选项 5 / 15 / 30 / 60 分钟；“只暂停拦截”与“整个服务休眠”展示一句话差别。
- 停止默认勾选放行；二次确认只用于需求明确要求的禁用自启，不给低风险操作增加额外对话框。
- 日志可从设备详情直接带设备过滤进入；导出范围与当前过滤一致。

## 状态与反馈

- 状态标签必须有文字，不靠颜色辨认。
- `audit` 文案为“只记录”；`enforce` 为“拦截未登记设备”，同时保留技术名称供诊断。
- 执行中禁用重复提交，保留当前输入；授权取消/失败不清空表单。
- 服务停止保留最近快照并标明“数据可能过期”；服务状态未知应写“连接中断”，不伪装为已停止。
- 无设备、无搜索结果、未登记设备、连接失败分别有相应下一步。
- 阶段 0 的验证界面明确标注“NSH 组件验证”；不能把验证事件呈现为真实 USB 设备。

## 视觉与可访问性

- 沿用系统窗口和字体，浅/深色由 theme tokens 统一；主色用于选中/提交，橙色用于需要关注，红色用于错误/停止。
- 内容区用分隔线组织，避免卡片套卡片；行高和字距保证快速扫读。
- 全部交互使用 NSH 语义组件；Tab、Enter、Space、Escape 可操作，有可见焦点。
- 用户调整窗口、字体/缩放时，优先保留主操作；长 ID 可截断但详情可查看完整值。
- 关键操作始终有文字按钮，不依赖 hover、图标含义或右键菜单。
- 每个输入有独立标签和就近校验；输入法组合期间不重写文本。

## 可操作的验证标准

- [ ] 搜索 → 选中 → 详情：无需离开设备页。
- [ ] 暂停入口 → 选类型/时长 → 确认；取消不改变状态。
- [ ] 表单有错误时，用户能直接找到出错字段；关闭/重开行为明确。
- [ ] 事件到达更新列表与状态，保留正在编辑的草稿。
- [ ] 长列表回收和过滤后，行内容、选中项和详情保持一致。
- [ ] 浅/深色、窄/宽窗口、较大字体下内容不重叠，焦点与主要操作可见。
- [ ] 正式 GUI 在停止/意外断开/授权失败三种情况下行为符合需求；须阶段 6 对真实 daemon 验收。
