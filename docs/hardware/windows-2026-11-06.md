# V6X Rust CDC — Windows 硬件枚举记录

日期：2026-11-06。用户连接硬件后，在当前工具主机 **CFAR083（Windows）** 重试只读枚举。

## 实测结果

| 项目 | 结果 |
| --- | --- |
| USB 报告名称 | `V6X Rust CDC` |
| 在线串口 | `COM26` / `USB Serial Device (COM26)` |
| VID:PID | `1209:0001` |
| 状态 | `OK`，PnP ProblemCode `0` |
| Windows 串口驱动 | `usbser`，`usbser.inf`，Microsoft，`10.0.19041.3636` |
| 串口兼容类 | `USB\Class_02&SubClass_02&Prot_00`（CDC ACM 类提示） |
| USB 父设备 | `USB\VID_1209&PID_0001\V6X-RUST-001` |
| 序列号候选 | `V6X-RUST-001`，来自物理 USB 实例尾段，待 Linux `ID_SERIAL_SHORT` 核验 |
| 串口子接口 | `USB\VID_1209&PID_0001&MI_00\6&275C0824&0&0000` |
| 父设备类型 / 驱动 | USB Composite Device / `usbccgp` |
| 物理路径（Windows） | `PCIROOT(0)#PCI(1400)#USBROOT(0)#USB(1)` |

COM1（ACPI Communications Port）和 COM3（PCI Intel AMT SOL）也存在，属于非 USB 串口，不能作为本项目管理候选。

## 对 devguard 的意义

- 这次硬件使用的 VID/PID 与需求文档的 PX4 示例不同，应使用实测值，不猜测示例 PID。
- 串口子接口的 `6&275C0824&0&0000` 是 Windows 生成的接口实例部分，不能当作 `ID_SERIAL_SHORT`。
- 物理父设备是复合设备；后续阻断前须检查全部相关接口，不能只凭 COM26 存在便反授权整个父设备。
- 当前结果证明 Windows 已枚举设备并绑定 CDC 串口驱动；尚未证明 Linux devnode、udev 稳定链接、权限、termios、bootloader PID 或授权操作。

## 复现

在 Windows PowerShell 中运行：

```powershell
.\scripts\inspect-usb-windows.ps1 -OutputPath .\docs\hardware\windows-2026-11-06.json
```

脚本只读取 PnP / WMI 属性，不打开串口。原始 JSON 在同目录，保留主机和采集时间。

## 下一次目标 Linux 采集

在 Arch/Omarchy 接入同一硬件后记录：

```sh
lsusb -d 1209:0001
udevadm info --query=property --name=/dev/ttyACM0
udevadm info --attribute-walk --name=/dev/ttyACM0
```

以实际生成的 ttyACM 编号替换示例；重点核验 `ID_SERIAL_SHORT`、`ID_PATH`、`ID_USB_DRIVER`、接口组成。bootloader 的 VID/PID/序列号需单独观测。
